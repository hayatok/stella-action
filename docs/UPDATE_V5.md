# UPDATE V5 — トゥーンシェーダ化（Stella v5）

目的: モデル（GLB）とアニメーション規格には一切触らず、Three.js 側のマテリアル変換だけで
ステラとドローンの見た目をアニメ調（セルシェーディング）にする。比較調査で判明した
「プロ品質の差 = テクスチャ・スキニング・表情・トゥーン表現」のうち、トゥーン表現を埋める回。

## 変更範囲
- 対象: `src/main.js` のステラ読み込み処理、`src/drones.js` のドローン生成。
- 対象外: public/models/stella.glb（無変更）、アニメーションクリップ、ゲームロジック、
  アリーナ（arena.js）のマテリアルは現状維持。

## 仕様
1. **グラデーションマップ**: 4段階の DataTexture（例: 0.35 / 0.55 / 0.8 / 1.0 の輝度、
   NearestFilter、色空間は線形のまま）を1つ作り、全トゥーン材質で共有する。
2. **ステラの材質変換**: GLTF 読み込み後の traverse で、各メッシュの
   MeshStandardMaterial を MeshToonMaterial に置換する。
   -引き継ぐもの: map（テクスチャ）、color、emissive と emissiveMap（あれば）、
     transparent / opacity、side。
   - 破棄してよいもの: roughness / metalness / 法線マップ（v4 GLB には無い）。
   - 変換後も元の material 配列構成（マルチマテリアル）を壊さないこと。
3. **ドローン**: drones.js のシェル材質を MeshToonMaterial 化する（emissive の
   ヒットフラッシュ挙動は現行どおり動くこと。glow 等の発光部は標準材質のままでよい）。
4. **ライティング調整**: トゥーンで陰影の段差が読めるよう、既存の平行光源と環境光の
   バランスを微調整してよい（例: 平行光源をやや強く、環境光をやや弱く）。
   影（シャドウマップ）は現状どおり有効。
5. **アウトライン（試行）**: ステラの主要パーツに BackSide 反転ハル法の輪郭線を試す。
   - 太さはモデルのスケールに対して控えめ（目安: 法線方向へ 0.004〜0.01 相当）。
   - 細すぎるパーツ（ブレード、まつ毛、髪留め等）や、破綻が見えるパーツは除外リストで外す。
   - 判定基準: 正面・3/4・背面のスクリーンショットで「輪郭が浮く・二重線・破れ」が
     目立たなければ採用。怪しければアウトラインなしで出す（グラデーション変換が本命）。

## 受け入れ基準
- ゲームの全フロー回帰なし: 起動、移動、ダッシュ、ジャンプ、攻撃3段、ドローン3体撃破、
  CLEAR 表示、リスタート、STATE デバッグ HUD 表示。
- ステラのテクスチャ（肌・虹彩・髪・服アトラス）がトゥーン変換後も正しく表示される。
- 60fps 目安を維持（モバイル想定のため変換処理は読み込み時のみ、毎フレームの追加処理なし。
  アウトライン採用時もメッシュ数 +数十程度まで）。
- ビルド成功（npm run build）。コンソールエラーなし。
